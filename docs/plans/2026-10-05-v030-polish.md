# TaskDock v0.3.0 Polish Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make Fusion opacity consistent, avoid full AX window enumeration for visual-only settings, test mode preference migration, and prepare local v0.3.0.

**Architecture:** Apply inactive opacity to the Fusion collapsed tile. Route visual and layout setting callbacks separately from window-list changes; debounce a full refresh after continuous layout adjustments. Extract preference key migration into a small pure Swift module with isolated UserDefaults self-tests.

**Tech Stack:** Swift, SwiftUI, AppKit, Swift Package Manager.

---

### Task 1: Fusion collapsed opacity

**Files:** Modify `Sources/TaskDock/TaskbarView.swift`.

1. Pass the active mode's inactive opacity into `FusionCollapsedAppView`.
2. Apply it when none of the collapsed App's windows is focused.
3. Build and inspect the relevant path.

### Task 2: Settings refresh scopes

**Files:** Modify `Sources/TaskDock/SettingsView.swift`, `SettingsWindowController.swift`, `TaskbarPanelController.swift`.

1. Add visual-only and layout-only callbacks alongside the existing full refresh callback.
2. Use visual callbacks for theme, opacity, font, and item appearance.
3. Use layout callbacks for height/width/alignment, reposition immediately, and debounce full refresh until interaction settles.
4. Keep window inclusion and mode changes on the full refresh path.

### Task 3: Preference migration tests

**Files:** Create `Sources/TaskDockPreferences/ModePreferenceStorage.swift`, `scripts/mode-preference-selftest.swift`; modify `Package.swift`, `Sources/TaskDock/SettingsStore.swift`.

1. Add failing tests for legacy migration, mode isolation, round-trip persistence, and invalid input clamping.
2. Implement a pure persistence helper; adopt it in SettingsStore.
3. Run the isolated `swiftc` self-test and release build. The installed Command Line Tools SDK lacks a working XCTest/Swift Testing test runner.

### Task 4: UX, version, and local validation
